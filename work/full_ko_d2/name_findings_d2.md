# SO3 DC Disc 2 — 캐릭터 이름 테이블/엔진 모듈 조사 (so3_name_patch 포팅용)

조사일: 2026-07-24. 대상 ISO: `D:\ps2\Star Ocean Till the End of Time Director's Cut (Disc 2).iso`
(size 4,685,955,072, SHA256 `349FF9443E3ACFD92045C5DFAD6D97EB51D2765B0781BCD59DCD424D81670288`).
소스: `work\full_unpack\disc2` (60,395 decoded stream 전수 스캔). 머신리더블 결과: `name_patch_d2_config.json`,

## 결론 (한 줄)

**이름 패치의 4개 extent(0002.sle, 글로벌 폰트, 0068, 1069)는 disc1과 전 바이트 동일**하고,
차이는 아카이브 68·1069의 ISO 위치 이동뿐이다. `so3_name_patch.py`는 **숫자 4개(iso_offset 2 + boundary 2)만
오버라이드하면 그대로 Disc 2에 적용 가능**하다 — SHA/테이블 오프셋/할당/키/인코더 전부 무변경.

## 1. 0002.sle (task 1·2)

- Disc 2 `raw\0002.sle` = ISO offset 2,355,200 (LBA 1150), 645,120B — **disc1과 위치·크기·바이트 완전 동일**
  (SHA256 `C0BE5D30…FD00` 일치). 동일 키 `66665442B379F0C7E7D51E4B7BA41C7D`로 복호 성공.

  - **이름 테이블**: 파일 0x11BC28..0x11BC77 (VA 0x5038A8..F7), **역순**(id10 ﾐﾗｰｼﾞｭ 먼저), stride 8B,
    addr(id)=0x5038F8−8×id. 바이트 disc1 §4와 일치.
  - **부수 리터럴**: 파일 0x11FA98=ｿﾌｨｱ(VA 0x507718) / 0x11FAA0=ﾌｪｲﾄ(VA 0x507720).

  - m1 할당: 파일 내 payload 시작 73,172, structural 645,120−73,172=**571,948**, 원 압축 뒤 302B 제로 꼬리

## 3. 글로벌 1.72 폰트 멤버 (task 4)

- Disc 2 아카이브 8 (`raw\0008.zls`, ISO 3,753,984, 61,440B — **raw 전체가 disc1과 바이트 동일**), 스트림 s000014:
  **ISO offset 3,788,176** (disc1과 동일 위치), mode 2, comp 24,496, unp 84,608, `so3mclib 1.72`, 292글리프.
- decoded SHA `8F91FE6C…A3BC` = disc1과 동일. **폭 테이블(@0x80 292B)·비트맵 섹션(@0x200, 292×288B) 바이트 동일**
  (비트맵 sha 733679D7…).

  disc1과 동일 바이트) → writable **24,544** (disc1과 동일).
- **21개 가나 슬롯 재용도 가능성**: 폰트·변환기·글로벌 맵이 전부 동일하므로 disc1과 같은 21슬롯/가나 코드

  전제 조건도 disc1과 동일: **Disc 2 본편 텍스트 패치가 같은 GLOBAL_CODE_MAP(=FORBIDDEN_GLOBAL_CODES 회피 규칙)을
  쓸 것** — 이름 패치는 본편 한글화 후 적용해야 함(단독 적용 시 일본어 가나 21자가 한글로 보임).

셋 다 disc2에 존재하며 **컨테이너가 disc1과 바이트 동일** → 동일 message id 그대로 존재:

## 5. 포팅 판정 (task 6)

**코드 수정 없이는 실행 불가하지만, 필요한 변경은 상수 4개뿐.** 현 스크립트는 disc2에서 아카이브 68 extent 검사
(빌드 시 0x200000 숨김 인덱스와 대조)에서 fail-closed로 정지한다(의도된 안전 동작). 어댑테이션 체크리스트:

1. `S0068_MEMBER`: `iso_offset` 493,129,728 → **458,348,544**, `boundary` 493,148,160 → **458,366,976**.
2. `S1069_MEMBER`: `iso_offset` 1,059,936,256 → **947,091,456**, `boundary` 1,060,605,952 → **947,761,152**.
3. 그 외 **전부 무변경**: `FONT_MEMBER`·`SLE_EXTENT`(위치 동일), SHA 6종, `SLE_TABLE_OFFSET`/`SLE_LITERALS`/
   `T0068_OFFSET`/`T1069_OFFSET`, `_ORIG_ROWS`(+1069 ｲｻﾞｰｸ), `SLE_KEY`, 가나 할당, mode-3 인코더, 폰트 재구축.
4. `REF_FONT`/`REF_0068`/`REF_1069`/`REF_SLE`는 disc1 경로지만 참조 바이트가 disc2와 동일하므로 그대로도 동작.
   깔끔하게는 `full_unpack\disc2\...` 동일 상대경로로 스위치(파일명까지 동일: s000014/s000061/s001679/0002.sle).
5. 구현 방식 제안(어댑테이션 에이전트 선택):
   - (a) `--config name_patch_d2_config.json`으로 위 4값(+ref 경로) 오버라이드, 또는
   - (b) 숨김 인덱스에서 자동 유도: `start=table[aid]*2048`, `boundary=start+table[6144+aid]*2048`(68·1069는
     아카이브 끝이 boundary), `iso_offset=start+아카이브 내 오프셋`(68·1069는 0, 폰트는 34,192) — 이러면 양 디스크
     공용. 폰트 boundary만 "다음 스트림" 기준이므로 인덱스가 아니라 상수(+0x6000) 유지 필요.
6. 적용 순서는 disc1과 동일: **본편 메시지 패치 후** 중간 ISO에 실행(4 extent 사전 SHA 확인이 그대로 유효).
7. 검증 루틴(`verify_name_patch`)·테스트도 오프셋 파라미터화 외 변경 불요. 엔드투엔드 테스트의 원본 ISO 경로만
   disc2로 지정.
