# SO3 DC Disc 1 — `93 80 <id>` 캐릭터 이름 중앙 리소스 조사 결과

조사일: 2026-07-16. 대상: Disc 1 (`work\full_unpack\disc1`, 61,964 decoded stream 전수 스캔 + 런타임 모듈 정적 분석 + EE RAM 덤프 교차 검증).

## 결론 (한 줄)

`93 80 <id>`가 그리는 이름의 **원본 데이터는 mclib이 아니라, 0002.sle member 1(폰트/텍스트 렌더러 모듈, VA 0x3E7C80)의 데이터 섹션에 있는 반각 가타카나(JIS X 0201 1바이트) 문자열 테이블**이다. 렌더러는 이 반각 바이트열을 런타임 변환기(VA 0x465550)로 글리프 코드로 바꿔 전역 1.72 아틀라스에서 그린다. 전각 SJIS 이름 문자열은 디스크 어디에도 없다(전수 스캔 0건).

## 1. 확정 id 대응 (주의: 8/9 순서)

모든 독립 증거(아래 4곳)가 일치: **1=フェイト 2=ソフィア 3=マリア 4=クリフ 5=ネル 6=アルベル 7=ロジャー 8=スフレ 9=アドレー 10=ミラージュ**.
`spoken_dialogue_index.json`의 character_reference_table도 이 순서다. (외부 문서에서 8=アドレー/9=スフレ로 적힌 표는 **오류**.)
성씨도 교차 확인: id8=・ロセッティ(스플레), id9=・ラーズバード(아드레이).

## 2. 렌더러가 실제로 읽는 것 (역어셈블 증거)

렌더러 모듈 = `work\executable_mapping\decoded\member_01_off_00011DC4_va_003E7C80.bin`
(원본: `work\full_unpack\disc1\raw\0002.sle` member 1, sle_offset 73156, SLZ mode 3, 압축해제 1,186,048B, 로드 VA 0x003E7C80, SLE key 66665442B379F0C7E7D51E4B7BA41C7D, 0002.sle ISO offset 2,355,200 = LBA 1150)

파이프라인 (파일 오프셋 = VA − 0x3E7C80):

| VA | 역할 |
|---|---|
| 0x461FA8 (렌더), 0x4615D0 (폭 계산) | control 0x4013(=93 80) 처리: 피연산자 1바이트 = 캐릭터 id, `jal 0x4657F0` |
| 0x461FC0 / 0x4615E8 | control 0x4021(=A1 80): 파티 슬롯 → id 변환 후 같은 경로. 슬롯 테이블 = ctx+0x568 (u32×슬롯) |
| 0x4657F0 | 이름 리졸버: id가 1..10 아니면 0 반환. `obj = *(ctx+0x5E8)`; **가상호출 obj→vtable[+8](obj,id)** → 반각 가타카나 NUL종단 문자열 포인터 반환 |
| 0x465550 | 반각 바이트열 → u16 글리프코드 변환기 (아래 §3) |
| 0x462000~ / 0x461604 | 변환된 코드를 스크래치패드 렌더 버퍼(0x70000C78)에 복사 후 전역 아틀라스로 렌더 |
| 0x409178..0x409370 | **캐릭터 레코드 초기화 스위치**: id별로 정적 이름 테이블(§4)을 record+0x20에 strcpy. 점프테이블 VA 0x503900(11 entries, id 0..10; id0→0x4093A0 skip) |

- 전역 컨텍스트: `ctx = 0x5091C0` (모듈 데이터 내 정적; 포인터 저장 위치 VA 0x5094EC = gp−0x7A74, gp=0x510F60; 파일 이미지에 초기값 포함 확인).
- `ctx+0x5E8` (VA 0x5097A8)은 **파일 이미지 밖(BSS)** — 이름 제공자 객체는 게임 코드가 런타임에 등록. RAM 덤프(work\gs_font\slot2\eeMemory.bin) 시점에는 미등록/스테일(0x1CFC70) 상태였음. 제공자가 반환하는 문자열의 실체는 §4의 테이블(레코드 +0x20 사본 포함; RAM 0x6130F0에 フェイト 레코드 사본 확인).

## 3. 반각→글리프 변환기 (0x465550) 매핑 — 한글 패치 시 핵심 제약

93 80 이름 파이프라인이 낼 수 있는 글리프는 이 변환으로 도달 가능한 코드뿐:

| 입력 바이트 | 글리프 코드 |
|---|---|
| '0'-'9' (0x30-39) | 1..10 |
| 'A'-'Z' (0x41-5A) | 14..39 |
| 'a'-'z' (0x61-7A) | 40..65 |
| 0xB0 'ｰ' | 157 (ー) |
| 0xA6-0xDD 반각 가나 c | c − 0x13 (가타카나 기본) |
| c + 0xDE(ﾞ): 0xB6-C4 | c + 0x16 / 0xCA-CE → c + 0x11 / ｳ+ﾞ → 203(ヴ) |
| c + 0xDF(ﾟ): 0xCA-CE | c + 0x16 |
| 0x7E '~' | 히라가나 모드 토글 (가나 → c−0x64 계열) |
| 기타 | 코드 0xF1 대체; VA 0x4EED30 바이트와 일치 시 커스텀 슬롯 1개 |

⇒ 한글 이름을 93 80 경로로 내보내려면 (a) 이 표에서 도달 가능한 전역 아틀라스 슬롯(예: A-Z=14..39)을 한글 글리프로 교체하고 이름 바이트를 그 코드로 재작성하거나, (b) 변환기/리졸버를 코드 패치하거나, (c) 기존 방식대로 mclib 쪽에서 93 80을 리터럴 한글 글리프열로 치환(대사 화자 6,449건 + 본문 내 참조).
