# 세이브 슬롯 "프ㅗ이트" 깨짐 — 원인 규명 결과 (D11-② 후속)

조사일: 2026-07-25. 대상: `문자오류1(로드).jpg`(메모리카드 로드 화면 슬롯 이름 깨짐),
`문자오류2(lvmp).jpg`(메인 메뉴 LV/HP 라벨 깨짐), "대사에서도 가끔 같은 깨진 이름" 리포트.
플레이 ISO: `D:\ps2\SO3_DC_Disc1_Korean_Full_Img_v111.iso` (v1.1.1, 7/24 빌드).

## 결론 (한 줄)

**슬롯 이름 깨짐은 가설 A(옛 세이브)가 맞다.** 세이브 파일 헤더에 저장 시점의 이름
바이트(ﾌｪｲﾄ = `CC AA B2 C4`)가 텍스트로 박혀 있고, 이름패치 이전(7/13~14) 빌드로 만든
세이브를 이름패치 후 빌드에서 열면 그 옛 바이트가 교체된 글로벌 아틀라스를 통과해
"프ㅗ이트"로 보인다. **디스크(ISO)에 미패치 이름 원본은 존재하지 않으며**(전수 재스캔으로
확증), 바이너리 추가 패치로 고칠 수 있는 것이 없다. **그 세이브를 패치판에서 다시
저장(같은 슬롯 덮어쓰기 포함)하면 헤더가 현재(한글) 이름으로 재작성되어 정상화된다**
(저장 경로 역공학으로 확인, 아래 §4).

## 1. 증상의 바이트 단위 재현 (시뮬레이션 == 스크린샷)

변환기(VA 0x465550: 반각 가나 c → 글리프코드 c−0x13, 슬롯 = 코드−1)와
이름패치가 교체한 21개 글로벌 슬롯(147,153,157,158,164,168,169,171,174,176,180,
183,184,185,187,188,190,195,196,198,199)에 옛 이름 바이트를 넣으면:

| 저장된 바이트 | 코드 | 슬롯 | 패치 전 글리프 | 패치 후 글리프 |
|---|---|---|---|---|
| 0xCC (ﾌ) | 185 | 184 | フ | **프** |
| 0xAA (ｪ) | 151 | 150 | ェ | **ェ (미교체 — 원본 유지)** |
| 0xB2 (ｲ) | 159 | 158 | イ | **이** |
| 0xC4 (ﾄ) | 177 | 176 | ト | **트** |

⇒ "프ェ이트". 작은 ェ가 ㅗ처럼 보여 스크린샷의 "프ㅗ이트"와 정확히 일치한다.
(같은 원리로 옛 소피아 세이브라면 `BF CC A8 B1` → "소프ィ아"로 보였을 것.)
이 조합은 "옛 반각 가타카나 바이트열 + 패치된 폰트"에서만 나올 수 있다 — 깨짐 자체가
가설 A의 지문(fingerprint)이다.

## 2. 가설 B(미패치 원본 존재) — 전수 검증으로 **기각**

  소스(전부 패치됨)는 정상이고, 세이브에 저장된 사본만 옛 것이라는 직접 증거.

## 3. 세이브 슬롯 이름의 실제 경로 (역공학, module 1069 = FldScenario 엔진)

세이브 시스템은 1069 모듈(로드 VA 0x1E2B00)의 세이브 매니저 클래스에 있다
(CRC32(0x04C11DB7) 사이트 0x30C27C~0x30EA00 군집).

### 세이브 데이터 파일 헤더 (0x80 바이트) — 슬롯 표시 정보의 원본

작성 함수 0x30E5F0 (`this+0x80`에 스테이징 후 0x30EE18에서 요청 버퍼로 복사):

| 헤더 오프셋 | 내용 | 출처 |
|---|---|---|
| +0x00 | 매직 문자열 `"2003-0120"` | VA 0x329300 상수 (원판 SO3 포맷 유지) |
| **+0x10** | **주인공 이름 텍스트 (반각 바이트, NUL종단)** | **가상호출 `this->vtable[+8](this, 1)` = GetName(id 1) — 저장할 때마다 새로 캡처** |
| +0x28 | 헤더 CRC32 (0x30EDA0에서 매번 재계산) | |
| +0x34 | `*(this+0x105E)` (지역/챕터 id) | 로드 화면의 "긴급 피난시설"은 이 id를 **표시 시점에** 패치된 mclib에서 해석 → 한글 정상 |
| +0x38, +0x3C | 플레이타임 등 수치 | |
| +0x40 | 리드 캐릭터 id | |
| +0x60..0x65 | 파티 6명 id | 로드 화면 하단 초상화가 여기서 해석됨 |

- **이름만 "텍스트로 저장"**되고 지역·초상화는 id로 저장 → 옛 세이브에서 이름만 깨지고
  지역명·초상화는 정상인 스크린샷과 정확히 부합.
- GetName의 실체: 접근자 0x30BF20/0x230510 = `mgr + 0xA6B0 + (id−1)*0x18`.
  이 이름 배열(10×24B)은 **매니저 생성 시 0x2D01E0~0x2D02A0에서 1069 정적 테이블
  (VA 0x336260=id1 … 0x336218=id10, 이름패치 extent)로 strcpy 초기화**되며,
  1069 전체에서 0xA6B0를 만지는 코드는 이 초기화+접근자뿐(전수 상수 검색) —
  **세이브에서 복원되지 않는다**. 메뉴 이름이 옛 세이브 로드 후에도 정상인 이유.

### 재저장 시 갱신 여부 — **갱신된다**

- 저장할 때마다 헤더 0x80B를 memset 후 전부 다시 채우고(이름 = 위 GetName 신규 캡처)
  CRC도 재계산한다. 옛 헤더를 이어 쓰는 경로는 없다.
- 따라서 패치판에서 **같은 슬롯에 덮어쓰기만 해도** 헤더 +0x10이 한글 철자
  (`CD B2 C4` = 페이트)로 바뀌어 슬롯 표시가 정상화된다. 새 슬롯/새 게임은 당연히 정상.
- 사소한 잔재: 메모리카드 안 실제 **데이터 파일의 파일명**(요청 필드 this+0x100B ←
  슬롯 엔트리+0x20, 0x30BFF0/0x30CEBC)은 덮어쓰기 시 기존(열거된) 파일명을 재사용한다.
  즉 카드 안 파일명은 옛 가나 바이트로 남을 수 있으나 **게임 화면에는 표시되지 않는다**
  (uLaunchELF/mymc 등 세이브 관리 툴에서만 보임).

## 4. 대사 쪽 "같은 깨진 이름" — 세이브 이름과는 다른 뿌리

- 대사 동적 삽입(93 80 / A1 80)의 해석 경로: 렌더러(0x461FA8/0x4C8028) → 리졸버
  0x4657F0 → `ctx+0x5E8` 제공자 = 1069 매니저(0x2F374C에서 `mgr+0x594` 등록) →
  위의 **이름 배열(패치된 정적 테이블 유래, 세이브 비복원)**. ⇒ **이 경로는 옛 세이브를
  로드해도 깨질 수 없다** (메뉴 정상 스크린샷이 실증).
- 따라서 대사에서 목격되는 깨짐은 별개 원인일 가능성이 높다. 후보(증거 확보됨):
  1. **하드코딩 리터럴**: m1 데이터에 메시지 인코딩 리터럴이 박혀 있다. 실례 —
     VA 0x5078F0 `"1メッセージデータがありません"`: メ가 글로벌 코드 191(슬롯 190)이라
     이름패치 후 **"1벨ッセージデータがありません"**으로 렌더된다. 이름패치가 재용도한
     21개 가나 슬롯을 쓰는 **잔존 일본어 텍스트/리터럴**은 어디서든 한글 음절이 섞여
     보인다("페/이/트/소/프…" 음절이 대사에 출몰하는 것처럼 보임).
  2. 옛 세이브가 담고 있는 **다른 저장 텍스트**(배틀컬렉션 BTLCOL 세이브의 등록명 등,
     dir `BISLPM-65438BTLCOL`) — 저장 시점 캡처 텍스트라 같은 방식으로 깨질 수 있음.
- 확정하려면 해당 대사 장면 스크린샷/재현 위치가 필요. 스크린샷이 오면 §1의 표로
  바이트 역산하면 원본이 즉시 특정된다.

## 5. 별건: 메인 메뉴 LV/HP 라벨 깨짐 ("코오 1 요No. 350/350")

`문자오류2(lvmp).jpg`의 깨진 라벨은 **이름 문제와 무관한 별도 버그**다. 조사 결과:

- 마스터 메뉴 뱅크의 라벨 메시지 msg2091="LV"(바이트 `19 23`), 2092="HP"(`15 1d`),
  2093="MP"(`1a 1d`)는 **원본·패치본 모두 글로벌 라틴 코드로 동일**(bank 77:70 실측)
  — 이 메시지로는 깨질 수 없고, 실제로 같은 화면의 "NEXT/MP"는 정상이다.
- 깨진 글리프(코,오,요 + 원본풍 "No.")는 이름패치 21슬롯(코/오/요 없음)도, bank 77
  로컬 슬롯(오=slot 624·요=636, 원본은 洗·病)도 아니다 ⇒ **현재 지역이 로드한 다른
  컨테이너의 로컬 폰트 슬롯**을 참조하는, 본편 패치가 다시 쓰지 않은 코드열(모듈 내
  하드코딩 라벨로 추정)이다.
- 확정에는 메뉴 표시 중 런타임 덤프(활성 폰트 디스크립터·드로우 콜) 1회가 필요.
  후속 세션 과제로 분리 권고. (수정 방향: 해당 리터럴을 글로벌 라틴 `LV`=25,35 /
  `HP`=21,29로 바꾸면 지역 무관하게 정상 — 위치만 특정되면 소규모 패치.)

## 6. 릴리즈 노트용 사용자 안내 (한글패치 v1.1.x)

>
> 한글패치 적용 **이전**(일본어 원판 또는 구버전 패치)에 만든 세이브를 불러오면,
> 세이브/로드 화면의 슬롯에 주인공 이름이 "프ㅗ이트"처럼 깨져 보일 수 있습니다.

> **게임 진행에는 아무 영향이 없습니다** (메뉴·대사·전투의 이름은 정상).
>
> **해결 방법**: 해당 세이브를 불러온 뒤 아무 세이브 포인트에서 **다시 저장**
> (같은 슬롯 덮어쓰기 가능)하면 그 슬롯의 이름이 "페이트"로 갱신됩니다.
> 새로 시작한 게임의 세이브는 처음부터 정상입니다.
